# KRT-DF005 triage

Adapted from the prior DF005 triage for the state at commit 2962a85. Earlier stopped-state notes and part A limitations describe historical work, not the present profile and certificate implementation.

The PostgreSQL shared-writer trace runs two supervised processes on one storage reference and requires both native entry receipts before release. Review showed that the former a_first and b_first checks were one measurement, because release order only changed a Promise.all order and no winner order was observed, so they merged into one order-agnostic kernel.syscall.shared_writer.race. The worker-clock expiry mutant is detected under skew. The shared-backend stale-head mutant can activate in one writer while the other reports no activation; the shared collect observes one result and one error, so the race does not detect a stale competing write. The current reasons are in `spec/conformance/kernel/kernel-shared-backend-undetected.json`. The expired-lease claim also has a recorded reason for lacking a designated detector.

The prior whole-outcome schema assertion convention was removed by 44e9481. The live-preemption trace now checks a catalogued adapter-error schema and an explicit error-kind observation. The earlier collect limitation for arbitrary native error details remains a proposed authority issue under OD-22.

SQLite claims persistent-reopen and process-crash; PostgreSQL also claims shared-backend. Certificates require a passing control run for the same profile and matching verifier digests. A mutant with a claim in a profile is killed for that profile only when an assertion of that profile's claims fails. A mutant with no claim in the profile keeps the ADR-0079 rule and earns no claim coverage there, which applies to kernel.accept-noncanonical-cbor and kernel.resolve-object-across-scopes under kernel.memory. The disagreement comparison reports PostgreSQL-only applicability for the writer race and server-clock check, rather than a disagreement on shared observations.

Committed compatibility rows keep source-bound digests only. CI run 41278386472 showed that digests of the local Rust binary, node_modules, and the Bun executable cannot be checked from another machine; those digests stay in the run-scoped bundles.
