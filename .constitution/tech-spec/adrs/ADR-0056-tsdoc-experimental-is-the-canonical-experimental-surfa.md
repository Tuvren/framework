### ADR-0056 TSDoc `@experimental` Is the Canonical Experimental-Surface Marker, Enforced by the API-Snapshot Gate

- **Status:** accepted. Amended on 2026-10-17 to align explicit stable-break baseline approval and ledger labels with ADR-0069's 0.x release policy. The original marker and default-blocking decisions remain in force.
- **Context:** ADR-0054 froze the stable core (`@tuvren/core` primitives, the Durable-Read Surface, `ExecutionHandle`/`awaitResult`, `createTuvren`, and the published leaf packages) and carved out the still-settling `@tuvren/core/capabilities` advanced classes as an explicitly excluded, experimental surface — but deferred "the exact ... experimental-marker mechanism" to "the SaaS-readiness freeze epic." This ADR is that finalization, for PRD CAP-P0-070, whose capability text requires "any not-yet-stable surface [be] explicitly separated and marked experimental so adopters can depend on the stable core without absorbing churn." The 2026-07-04 audit (`grep -rn "@experimental" typescript/core/src`) found zero markers exist today: `@tuvren/core/capabilities` (`typescript/core/src/capabilities/index.ts`) is presently a ~43-line type-only re-export barrel (per ADR-0046 and the phased realization of ADR-0047) with no stability annotation on any of its re-exported types. Two constraints must be resolved together, not sequentially: (1) the marker must be human-visible in editor tooling and generated docs, and (2) the forthcoming API-surface snapshot/diff gate must programmatically distinguish a stable-core breaking change (blocked) from an experimental-surface change (permitted) — a marker chosen without the gate's read model in mind risks a mismatch discovered only after tooling is built.
- **Decision:** TSDoc `@experimental` release tags on individual exports are the canonical experimental-surface marker for the stable-core freeze, chosen over a dedicated experimental subpath (e.g. `@tuvren/core/capabilities/experimental`) or a package-level-only notice.
  1. **Why a tag on the export, not a subpath split.** A subpath boundary is import-path-shaped: graduating one export to stable would force every adopter to change an import path, which is itself a breaking change at the exact moment the export becomes safe to depend on — precisely the churn CAP-P0-070 asks the marker to prevent. A TSDoc tag graduates an export by deleting a comment: the import path (`@tuvren/core/capabilities`) never moves, and removing `@experimental` from a previously-tagged export is additive (semver-minor), not breaking. The subpath already exists as the coarse capability-orchestration boundary from ADR-0046; this decision does not disturb it and instead operates one level finer, at the individual export.
  2. **Why TSDoc specifically, not a bespoke comment convention or a runtime flag.** TSDoc release tags (`@alpha`/`@beta`/`@experimental`/`@public`) are a standardized, tool-recognized vocabulary that API-surface extraction tooling (an api-extractor-class tool, or an equivalent tsc `.d.ts`/type-checker-driven walker selected in the freeze-gate execution work) reads natively when building a public API model. Adopting the standard vocabulary means the freeze gate's stable/experimental classification is derived mechanically from the same annotation a developer sees in-editor and in generated docs, rather than maintained as a second, hand-kept list that can drift from the source. A bespoke convention or a runtime-only flag would not be visible to static extraction tooling and would require the gate to re-invent tag semantics; a runtime flag additionally cannot express "this exported type is experimental" for type-only exports, which is most of `@tuvren/core/capabilities` today.
  3. **Marking mechanics.**
     - Every current export of `@tuvren/core/capabilities` receives a `/** @experimental */` TSDoc tag at initial freeze. The subpath's package-level documentation additionally carries a subpath-level experimental notice so the boundary is visible without reading individual export docs.
     - The freeze/diff gate treats tags as the sole source of stable/experimental classification:
       ```
       stable snapshot   = frozen public surface \ { exports tagged @experimental }
       diff on new run:
         - export gains @experimental (was untagged/stable)  => BLOCKED (removes a stable guarantee)
         - export loses @experimental (was tagged)            => ALLOWED, recorded as semver-minor
         - signature change on an @experimental export        => ALLOWED, not gated
         - signature change on an untagged (stable) export    => BLOCKED unless semver-major
       ```
     - **Consistency floor:** if the authority (this ADR, or a successor capability-orchestration ADR) declares a subpath wholly experimental, the gate fails the build when any export under that subpath lacks the `@experimental` tag — an untagged export under a declared-experimental subpath is a documentation defect, not a silent stable promotion.
     - **Graduation rule:** an export only becomes part of the enforced stable snapshot once it appears untagged in a snapshot run; there is no separate "promote" ceremony beyond removing the tag and letting the gate's next run absorb it.
     - Marker declarations (which exports/subpaths carry `@experimental` and why) are recorded in the core authority packet's surface listing, so conformance plans, generated docs, and the gate's expectations stay aligned with a single authored source rather than three independently maintained lists.
  4. **0.x baseline approval amendment (2026-10-17).** ADR-0069 supersedes this ADR's `semver-major` and additive `semver-minor` release labels while the public packages remain on 0.x. The snapshot stays an exact-signature freeze. Any change to an existing stable signature remains blocked by default, including an optional property addition. A maintainer may admit the complete reviewed set of blocked findings with `bun run api-freeze --minor`. The command refreshes the snapshot and records `bump: "minor"`. ADR-0069 classifies an intentional 0.x stable break as a MINOR release. The admission-key change uses this path because it is a project-benefiting pre-adoption break. This classification does not claim that the exported TypeScript signatures are unchanged or source-compatible.
     - `bun run api-freeze:check` remains strict and accepts no approval flag. `bun run api-freeze` without `--minor` refuses blocked stable drift. `--minor` is valid only for an update that contains blocked stable findings; `--major`, unknown flags, `--check --minor`, and an unnecessary `--minor` fail. Every blocked finding is printed and copied into the ledger before review can accept the generated snapshot.
     - The gate records `patch` for allowed public drift on the 0.x line, including a new stable export and experimental-to-stable graduation. Experimental changes remain outside the stable guarantee; when an update records them, PATCH is the minimum public release. The first snapshot uses `baseline`, which is a capture label rather than a release bump. Existing ledger rows remain unchanged as historical records of earlier gate runs and do not classify a later release under this amendment.
     - The consistency floor remains independent and non-overridable. An untagged export under a wholly experimental entrypoint fails before any snapshot write, including an update that supplies `--minor`.
     - The API freeze gate owns the active 0.x release and ledger mapping. The pure diff model continues to provide deterministic change classes, allowed or blocked verdicts, and floor violations; its legacy bump hint is not release authority. This separation keeps the correction to `tools/scripts/api-freeze-gate.ts` and `tools/scripts/api-freeze-gate.test.ts`. No compatibility parser, helper, field allowlist, dependency, package script, extractor change, or model-test change is required. The later admission-key snapshot refresh stays in KRT-CS001's existing snapshot scope.
     - The gate tests must prove the valid argument combinations, default refusal without a write, and a MINOR ledger write containing every blocked finding. They must also prove PATCH labeling for allowed drift, rejection of an unnecessary approval, and a floor violation that cannot be approved. Scratch-writer coverage must preserve existing ledger rows as equal parsed data. It must also prove that canonical metadata cites ADR-0069 and `--minor`, formatter output is stable, and the parsed-value mutation guard fails closed. When KRT-CS001 resumes, its generated snapshot must contain exactly the five `InputSignal` and `TuvrenMessage` findings reported for the preserved implementation diff. The refresh must record MINOR and then pass `bun run api-freeze:check`.
     - Before a 1.x release, replace this 0.x-specific approval and release mapping through a later policy decision. A 1.0 release is not scheduled.
- **Alternatives considered for the 2026-10-17 amendment:** Two independent GPT-5.6 Sol read-only designs evaluated the same authority, gate, tests, snapshot, and preserved admission-key diff. Both retained exact-signature blocking and replaced the false `--major` declaration with an explicit 0.x MINOR approval. Both rejected a structural optional-property classifier. No package adopters need a compatibility language, and partial TypeScript compatibility analysis cannot prove source compatibility. The designs also rejected an admission-key allowlist, retagging stable exports as experimental, extractor-blind declaration tricks, hand-editing the snapshot, and compatibility aliases created only to preserve an unused signature. One design placed release impact in the pure model. The other kept the parser and update decision in existing files. Stage-4 inspection showed that the gate can derive current-line ledger labels from the existing findings. It does not need changes to the model, model tests, cache inputs, or project configuration. This amendment therefore chooses the smaller gate-only design. The decision meets the Depth Standard because it fixes the command states, release labels, failure order, owned paths, and required tests. It passes the Deletion Test because an intentional pre-adoption break otherwise requires a false MAJOR record, erased history, extractor evasion, or a blocked epic.
- **Consequences:** Adopters can depend on `@tuvren/core/capabilities` today for the advanced capability-orchestration classes and keep their import paths stable through graduation — only the tag disappears, which is additive. The freeze gate requires a TSDoc-aware surface extractor; the concrete tool (api-extractor-class vs. a custom tsc/`.d.ts` walker) is a tooling choice left to the execution plan, not fixed here. Linting/CI must enforce the consistency floor so an untagged export cannot silently ride into the stable snapshot under a declared-experimental subpath. Generated documentation must surface the experimental badge per export so adopters see the marker in the same place they see the type signature. This decision does not reopen ADR-0046/ADR-0047's phased realization of the capability-orchestration classes; it only fixes how their in-flux status is expressed and mechanically enforced once the stable-core freeze (ADR-0054) takes effect.
  - The 2026-10-17 amendment deliberately accepts conservative false positives: a change that might be source-compatible still needs explicit MINOR approval when its exact stable signature changes. This is cheaper and more reviewable before adoption than a partial compatibility engine. The admission-key keyless CBOR bytes and message hash remain a storage-identity invariant; that invariant does not downgrade the public signature change to PATCH. KRT-CS007 must therefore use a MINOR changeset when the epic resumes.
