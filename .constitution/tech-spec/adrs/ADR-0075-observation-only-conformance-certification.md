### ADR-0075 Observation-Only Conformance Certification

- **Status:** accepted. Amends ADR-0025 (adapter role) and ADR-0030 (adapter evidence) by making their intent enforceable. Enforces ADR-0031's existing rule that zero applicable checks never yields `pass` (ADR-0081).
- **Context:** ADR-0025 says adapters translate neutral operations into native calls and never evaluate assertions, and ADR-0030 says adapter evidence is diagnostic only. The plans and adapters do not follow either rule. At commit 04b277ce, 12 of 21 kernel operations return adapter-computed verdicts that plans compare to `true` (for example `committedStateVisible` in `typescript/kernel/conformance-adapter/src/host-restart-recovery-scenarios.ts:722`). The adapter chooses the expected checkpoint per fault point (same file, 486-507). Python derives its expectation from the kernel's own reconcile output (`python/kernel-conformance-adapter/src/tuvren_kernel_adapter/operations_liveness.py:316`). Rust `recovery-state` echoes fixture values (`rust/kernel-conformance-adapter/src/main.rs:455-469`). `workerClockWouldExpire` compares two adapter constants (`host-run-liveness-scenarios.ts:441`). In non-kernel plans, 845 of 931 assertions are `resultField` and 221 compare a literal boolean. Composite handlers script whole scenarios in `typescript/conformance-adapter`, and some hardcode literals such as `constructed: true`. Scenario scripts are duplicated per language and have diverged. The audit, the adversarial review, and both independent designs are recorded in `.constitution/research/2026-10-22-observation-only-certification-designs.md`.
- **Decision:**
  1. **What a certificate claims.** The identified implementation artifact, driven through reviewed bindings, produced observations that the generic runner judged against the identified authority revision and certification profile, and that profile's negative controls were detected. This is first-party verification. A JSON-RPC boundary cannot prove that a malicious adapter reports honestly. What it does guarantee is that no verdict, expected value, scenario script, clock, crash, or schedule is owned by an adapter or implementation.
  2. **Adapters are syscall bridges.** An adapter may construct native objects, invoke one native operation per dispatch, manage handles, translate values losslessly (ADR-0078), forward native errors unchanged, collect bounded iterators, and return records and events. It must not compare, count, select, sort an ordered result, choose an expected outcome, repair or reconcile state, simulate restart, own a clock, script a scenario, fabricate events, or summarize compliance. Adapter-side error normalization (`normalizeLogicalErrorCode`, `typescript/kernel/conformance-adapter/src/host-support.ts:149`) and per-language no-error sentinels are removed. Native codes are judged against the canonical codes in authority, and each catalog entry's `errors` field lists those codes. For the kernel the authority today is the kernel plans, which assert `turn_node_thread_mismatch`, `run_lease_owner_mismatch`, and `run_lease_token_mismatch`. The Go, Python, Dart, and Rust kernels already emit these codes and their adapters forward them unchanged. The TypeScript kernel emits `kernel_runtime_lineage_mismatch`, `kernel_runtime_run_lease_owner_mismatch`, and `kernel_runtime_run_lease_token_mismatch`, which the adapter masks today. That divergence is an implementation finding, resolved by aligning the TypeScript kernel's emitted codes under the 0.x release discipline (ADR-0069, ADR-0056), not by a per-implementation code binding. A mapping with no authority code yet, such as the adapter's `kernel_runtime_turn_head_lineage_mismatch` to `turn_head_lateral_move`, which no plan asserts, is a specification gap (ADR-0081) settled in authority before any implementation changes.
  3. **Operation catalogs.** Each port gains a packet-referenced catalog at `spec/conformance/<port>/operations.json`, validated by `tools/schemas/conformance-operation-catalog.schema.json`. An entry declares `operationId`, `kind` (`syscall`, `control`, or `double`), the bound public surface, input schema, closed observation schemas for result, events, and state, allowed error codes, handle types, and capability. Granularity is one externally meaningful public action. For the kernel that is the kernel specification's syscall surface (store, schema, tree, node, branch, thread, staging, run, run-liveness, maintenance). For framework ports it is the host action and handle level (start turn, obtain handle, steer, approve, cancel, durable read; subscribe and pull; invoke tool; generate or stream once). Work a public API performs internally stays opaque. A compound operation is allowed only when the public API itself is compound. The catalog defines invocation shapes and is never a behavioral oracle.
  4. **Harness-owned verdicts.** All scenario composition lives in plan traces. The plan compiler rejects uncatalogued operations, assertion paths outside the declared observation schema, and literal boolean comparisons except on fields the catalog types as native booleans of a `syscall` (for example `store.has`). The runner validates every observation against its schema before evaluating assertions; a violation is an adapter-protocol failure, never an implementation pass or fail.
  5. **Expected values never reach the adapter.** Expected values come only from plan literals, from fixture paths read by the runner, or from earlier trace observations. Steps send explicit `arguments` projections instead of whole fixtures or scenarios. A compiler no-echo rule rejects an assertion whose expected fixture node is reachable from the same step's arguments. Adapters are launched without plans or expected fixtures and may not import them.
  6. **Non-vacuity.** Both operands of a comparison must resolve, and an unresolved operand is a failure. `null` is distinct from absence. Presence-only assertions must be explicit. A quantifier over an array requires an explicit cardinality assertion. A negative event assertion requires a proven trigger and a completed observation window. Conditional assertions (`when`) are allowed for outcomes the authority leaves open, such as an uncertain commit. The negative-control gate (ADR-0079) must show every branch exercised somewhere in the fleet.
  7. **Test doubles.** Scripted providers, tools, MCP servers, and transports are `double` operations. Their scripts are plan-owned fixtures, and their journals report actual requests and consumption counts. A double does no grading. An unconsumed script invalidates the check. A pass against a double certifies integration with that script, not the behavior of an external service.
  8. **Rewritten plans cannot validate themselves.** Every migrated obligation keeps a stable `claimId`, and each rewrite carries an old-to-new obligation map reviewed with the plan. Expectations are never regenerated from successful implementation output. Canonical encodings stay committed vectors cross-validated by a second implementation. Detection is proven by negative controls (ADR-0079).
  9. **Statuses.** Zero applicable checks is `unsupported` or `not_applicable` per ADR-0031, never `pass`. This applies in the harness (`tools/conformance/harness/run.ts:881`) and in evidence validation (`tools/scripts/lib/conformance-contract.ts`). An adapter manifest with no capabilities cannot join the certified fleet; the Rust framework moves to the discovery inventory.
  10. **Test hygiene.** As each family migrates, unit tests that re-check their own fixtures, assert hardcoded literals, test adapter-computed verdicts, or duplicate a migrated harness check are removed, each with its reason in the migration's obligation map. Tests covering behavior the harness does not reach stay.
- **Alternatives considered:**
  - Two independent designs, one from Claude Fable and one from Codex gpt-6.1-sol, converged on syscall-bridge adapters, per-port catalogs with closed observation schemas, runner-owned expectations, and per-family plan rewrites. The divergences were settled as follows. Fable placed the catalog under `spec/<port>/`; the Codex placement under `spec/conformance/<port>/` was chosen because CLAUDE.md keeps shared conformance authority there. Fable's compiler-level no-echo rule and Codex's explicit `arguments` projections address different leak paths, so both are kept. Fable's certified double-conformance plans are deferred to the framework migration; Codex's journaled doubles are the base. Codex's `claimId` obligation map is adopted to keep coverage from silently disappearing during rewrites. Fable's conditional `when` assertions are adopted for authority-permitted alternative outcomes.
  - Keep composite operations and validate a "verdict schema". Rejected by both designs: renaming a verdict into a `result` field keeps the adapter as the oracle (ADR-0030).
  - A per-language lint banning comparisons in adapter source. Rejected: it can't be enforced across five languages. Closed observation schemas plus negative controls give a measurable signal.
- **Consequences:** Assumed until observed. Plans grow longer: a crash check becomes many steps. A small authoring generator may be added, but the JSON remains the authority. Adapters shrink substantially. Each language must expose the full syscall surface rather than scenario shortcuts, and missing operations become visible as `unsupported` rather than hidden inside scenarios. Families migrate one at a time behind the compiler rules, with legacy composite operations marked deprecated until every adapter in the fleet has migrated. CAP-038 and the constraint that compatibility claims trace to authority plus measured evidence gain an enforceable mechanism. BND-28's "evidence emissions" output is restricted to diagnostics; a Stage 2 alignment may restate it.
