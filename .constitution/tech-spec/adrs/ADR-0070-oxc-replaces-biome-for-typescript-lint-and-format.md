### ADR-0070: OXC replaces Biome for TypeScript lint and format

- **Status:** Accepted. Supersedes the lint-and-format part of ADR-0012. ADR-0012's `tsup` build decision remains in force.
- **Context:** ADR-0012 selected Biome with Ultracite for TypeScript lint and format. The September 29, 2026, ruling selected native Oxlint and Oxfmt with the Ultracite presets as shipped. EPIC-BP then measured how the installed tools implement that policy. With Oxlint 1.86.0, `extends` loses nine option-bearing rule tuples and the browser environment. A verbatim root spread preserves all 536 effective shipped rules, their options, and the environment. The October 1, 2026, OD-08 ruling adopts that root spread. EPIC-BP also established that Oxlint doesn't inspect JSON or JSON with comments (JSONC). The September 29 tool replacement ruling didn't choose a JSON admission design, so that later design required independent candidates. A directory can leave Biome only when native code lint, JSON source validation, and JSON formatting cover its former surface.
- **Decision:**
  1. **Run OXC tools directly.** Use Oxlint for JavaScript and TypeScript linting. Use Oxfmt for JavaScript, TypeScript, JSON, and JSONC formatting. Don't invoke the Ultracite CLI.
  2. **Preserve the shipped presets verbatim.** `oxlint.config.ts` spreads `ultracite/oxlint/core` at the root. `oxfmt.config.ts` spreads `ultracite/oxfmt`. Repository configuration can repeat the preset's ignore patterns and add repository exclusions. It can't override rules, rule options, severity, environment, globals, plugins, settings, or categories. A complete effective-configuration comparison enforces this requirement. Loader-specific `extends` syntax isn't required.
  3. **Keep transition pins distinct.** Use `ultracite@7.12.2`, `oxlint@1.86.0`, `oxfmt@0.71.0`, and `oxlint-tsgolint@7.0.2003`. Keep `@biomejs/biome@2.5.14` and the alias `ultracite-biome@npm:ultracite@7.4.2` stable until retirement. `biome.jsonc` extends `ultracite-biome/biome/core`. Remove Biome and the alias together only after every former Biome target has complete native coverage.
  4. **Enable type-aware linting.** Each native code target runs Oxlint with `--type-aware`. Root TypeScript projects expose source-only project references, and the first matching reference is `tsconfig.typecheck.json`. Ordinary typecheck remains source-only. Declaration generation is a build prerequisite only where type-aware execution needs built dependency declarations.
  5. **Give JSON a native admission path.** Bun 1.4.2 validates syntax and reports duplicate source keys without writing artifacts. Plain `.json` is strict JSON. Established JSON-with-comments profiles are `.jsonc`, `tsconfig*.json`, the exact filename `jsconfig.json`, and JSON files under `.vscode/`; names such as `jsconfig.foo.json` remain strict. Oxfmt checks the exact admitted JSON and JSONC files. Oxlint receives no credit for JSON. Owner schemas, authority validators, conformance validators, and fixture validators remain the semantic oracle.
  6. **Ratchet coverage by directory.** A directory leaves Biome only after one successful admission proves both its JavaScript/TypeScript lint coverage and its JSON/JSONC source-and-format coverage. Native discovery must account for ignored files and protected exceptions and must fail on gaps, duplicate ownership, empty selection, partial scope, unsupported options, or stale cached selection. JSON source and format gates remain after the Biome transition machinery is deleted.
  7. **Switch formatting and import organization together.** Oxfmt owns both from the mechanical reformat commit. The commit is exempt from the merged-diff budget and is listed in `.git-blame-ignore-revs`. Generators run Oxfmt from the repository root, preserve every pre-existing target input, and verify parsed values when formatting reviewed artifacts. `bun run format:check` is the shared read-only format gate.
  8. **Keep `tsup`.** Package builds don't change under this ADR.
- **Alternatives considered:**
  - Keep Biome and Ultracite 7.4.x. Rejected because the owner selected OXC as the toolchain direction.
  - Add repository overrides for Biome parity. Rejected because overrides would weaken the shipped policy and create a local exception surface.
  - Load the Oxlint preset through `extends`. Rejected by the OD-08 ruling because the installed loader drops nine option tuples and the browser environment.
  - Run Oxlint without `--type-aware`. Rejected because the installed preset contains 55 type-aware rules. The earlier count of 54 was a historical measurement, not a quota.
  - Treat Oxfmt as JSON lint. Rejected because formatting doesn't replace syntax, duplicate-key, owner-schema, or semantic validation.
  - The September 29 tool replacement choice was user-ruled before this follow-up. It didn't require a second design. SPK-KRT-OD006 measured the adoption cost, and OD-08 later settled the preset loader.
  - **Design A:** The read-only native Codex session task `/root/bp_followup_policy_sol` used GPT-5.6 Sol with high reasoning before implementation. It assigned code lint to Oxlint, source admission to a dedicated checker, formatting to Oxfmt, and semantic validation to existing owner validators. It proposed `JSON.parse` for strict JSON, `Bun.JSONC.parse` for recognized JSONC profiles, and the existing TypeScript abstract syntax tree parser with a duplicate-key walker. The design added no dependency, but it required maintained traversal and key-equivalence logic.
  - **Design B:** The independent read-only native Codex session task `/root/bp_followup_json_design` used GPT-6.1 Sol with high reasoning before implementation. It measured duplicate diagnostics from `Bun.build`. It proposed the same ownership split, `JSON.parse` for strict JSON, `Bun.JSONC.parse` for recognized JSONC profiles, and a read-only Bun diagnostic pass instead of the maintained duplicate-key walker.
  - **Synthesis and screening:** Both designs converged on a dedicated checker boundary and retained the existing authority, schema, conformance, and fixture validators. The boundary satisfies the Depth Standard because one admission command hides Git discovery, profile selection, parsing, duplicate diagnostics, and formatting selection. Deleting it would disperse those controls across Nx targets, Oxfmt callers, and owner validators, so it passes the Deletion Test. Design B is the accepted base because it removes the maintained abstract syntax tree and key-equivalence layer without adding a dependency or making the checker a semantic oracle. This choice reduces the architecture risk that TypeScript tooling or generic validation becomes cross-implementation authority. Commits `814b712` and `cec7a6f` implement the synthesis; they are implementation evidence, not design sources.
- **Consequences:** The Biome alias transition is observed: the alias preserves the 1,273-file inventory, normalized preset, and diagnostic baseline. The transition inventory at commit `6ab5e36` contains 42 Biome-backed targets: 33 TypeScript targets, eight `spec/` targets, and one compatibility-report target. The permanent native gates prevent that inventory from shrinking without checker coverage. The 144-directive split of 82 retained and 62 removed directives remains historical spike classification; later directory work must use live diagnostics. Type-aware preparation resolved the nine historical TypeScript diagnostics without hiding or suppressing them. The negative authority fixture still exercises both ownership guardrails through valid TypeScript; deliberately uncompilable fixture code isn't part of its semantics. Oxfmt remains a beta tool at version 0.71.0, so an upgrade can change reviewed JSON layout and must pass generator and parsed-value guards. The first directory remains the behavioral pilot for `func-style` and `no-use-before-define`; a runtime or conformance regression returns those rules to the owner instead of adding overrides.
